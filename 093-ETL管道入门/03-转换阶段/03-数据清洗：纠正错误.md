# 数据清洗：纠正错误

来源：[原文](https://apxml.com/zh/courses/intro-etl-pipelines/chapter-3-the-transformation-stage/data-cleaning-correcting-errors)

[返回章节目录](README.md) · [返回课程目录](../README.md)

虽然前一节讨论了缺失数据，但我们现在将注意力转向存在但错误的数据。错误可以通过多种方式潜入数据集中：手动数据输入错误（打字错误）、传感器或测量设备故障、随时间变化的格式不一致，或原始数据捕获系统中的程序错误。纠正这些错误是创建适合分析或加载到目标系统的可靠数据的重要一步。

试想一下日常信息中常见的错误：电话号码位数过多、出生日期显示为未来日期，或者州名缩写不一致（例如 'CA'、'Calif.'、'California'）。这些看似微不足道，但在大型数据集中，此类不一致可能导致报告不准确、分析失败以及决策有缺陷。

### 数据错误类型

错误可以表现为多种形式。以下是一些你经常会遇到的常见类别：

1. **不正确的数据类型：** 预期包含数字（如数量或价格）的字段可能包含文本字符（'N/A'、'unknown'，甚至只是一个拼写错误，如 '1O' 而不是 '10'）。
2. **超出范围的值：** 数据可能超出合理范围。例如，'年龄' 字段包含 '200'，或百分比值大于 100。
3. **无效值：** 字段可能包含语法正确但不在已定义可能性集合中的值。例如，'州' 字段包含 'XX'，而只允许有效的美国州缩写。
4. **格式不一致：** 相同的信息在不同记录中可能以不同方式表示。日期（'MM/DD/YYYY' 与 'YYYY-MM-DD'）、州名（'NY' 与 'New York'）或单位（'kg' 与 '磅'）是常见例子。
5. **矛盾数据：** 同一条记录中的不同字段可能存在冲突。一条记录可能将城市列为 '洛杉矶'，但邮政编码属于 '纽约'。
6. **重复记录：** 有时，同一个实体（如客户或交易）可能在数据集中多次出现，可能存在细微差异，使简单的删除变得困难。虽然通常作为去重单独处理，但识别近似重复项通常需要首先纠正不一致的字段。

### 识别错误

在纠正错误之前，你需要先找到它们。这通常涉及多种技术的组合：

- **数据分析：** 这包括分析数据以了解其结构、内容和质量。简单的分析方法包括：
  - 查找数值列的最小值和最大值（快速显示异常值）。
  - 计算分类列中不同值的频率（突出显示 'CA' 与 'Calif.' 等不一致）。
  - 根据预期检查数据类型。
- **验证规则：** 定义数据必须遵守的明确规则。这些可以是简单检查（例如，`age > 0 AND age < 120`），也可以是更复杂的模式（例如，使用正则表达式检查产品代码是否匹配特定格式）。违反这些规则的数据将被标记 (token)为错误。
- **一致性检查：** 比较相关字段以确保它们相互关联且合理。城市是否与州或邮政编码匹配？订单日期是否在发货日期之前？
- **使用参考数据：** 将值与已知、受信任的列表（查找表）进行比较。例如，检查 '国家' 字段是否包含官方国家代码列表中的值。

### 纠正策略

一旦识别出错误，你需要一个修复它们的计划。适当的策略取决于错误的类型、上下文 (context)以及纠正的潜在影响。

- **基于规则的纠正：** 实施自动化规则来修复常见、可预测的错误。
  - *例子：* 如果 `State` 是 'Calif.' 或 'California'，则将其替换为 'CA'。
  - *例子：* 如果 `PhoneNumber` 包含 `(` `)` `-` 或空格等字符，请删除它们以标准化格式。
- **查找表：** 使用外部参考表来标准化或验证值。
  - *例子：* 邮政编码查找表可以提供正确的 `城市` 和 `州`，从而帮助你纠正不一致之处。
- **统计方法：** 对于明显不可能的数值异常值（如 `年龄 = 200`），你可以用统计量（例如*来自有效记录的*平均年龄或中位年龄）替换它们。谨慎使用此方法，因为它会改变原始数据分布。它通常更适合处理不可能的值，而不是仅仅不寻常的值。
- **解析和重新格式化：** 对于日期或地址等复杂字段中的不一致，你可能需要将字段解析为组件，对其进行标准化，然后以所需格式重建字段。
- **标记 (token)：** 有时，错误无法自动可靠地纠正。在这种情况下，最好的方法可能是将记录或特定字段标记为错误，可能将其路由进行手动审查或从某些分析中排除。
- **手动审查：** 对于复杂或模棱两可的错误，特别是在较小的数据集或重要字段中，可能需要人工检查和纠正。这通常作为“异常处理”过程实施，其中被标记的记录会提交给数据管理员。

纠正错误通常是一个迭代过程。你可能应用一套规则，再次分析数据，发现新的问题，并改进你的纠正逻辑。目标不一定是完美（那可能无法达到），而是为了大幅提高数据质量和一致性，以满足其在加载阶段的预期用途。
