# 监控与日志记录要点

来源：[原文](https://apxml.com/zh/courses/intro-etl-pipelines/chapter-5-building-simple-etl-pipelines/monitoring-logging-fundamentals)

[返回章节目录](README.md) · [返回课程目录](../README.md)

当ETL数据管道被配置为自动运行，例如按计划运行时，确定它们的正确操作是一个主要挑战。如果自动化运行期间出现问题怎么办？这时，监控和日志记录就成为重要的做法。就像检查汽车上的仪表盘一样，监控和日志记录能让您了解自动化数据处理过程的状况和表现。

### 为何监控和记录日志？

自动化数据管道在没有人直接干预的情况下运行。如果没有监控，故障可能数小时甚至数天不被发现，导致目标系统中数据缺失或不正确。当故障发生时，日志记录提供所需的详细记录，以诊断问题所在。

可以这样理解：

- **监控** 就像查看仪表盘上的警示灯。它告诉您总体状态（运行中、已完成、失败）和重要的性能指标（如持续时间）。
- **日志记录** 就像汽车的电脑存储错误代码和事件详情。它提供您所需具体信息，以便弄清警示灯为何亮起。

它们共同帮助确保您的数据管道可靠且易于维护。

### 监控数据管道执行

监控涉及观察ETL数据管道运行的高级状态和性能。主要目标是快速识别问题并掌握性能趋势。

通常需要监控的重要方面包括：

- **执行状态：** 数据管道运行是成功完成、失败还是仍在运行中？这是最基本的检查。
- **开始和结束时间：** 知道数据管道运行何时开始和结束。
- **持续时间：** 数据管道运行了多长时间？监控持续时间有助于识别性能下降（运行时间比平时更长）或异常行为（运行过快完成，可能表示有错误）。
- **数据量：** 跟踪提取、转换或加载的记录数量，如果数据量意外大幅变化，这可以表明存在问题。
- **资源使用：** 虽然可能更进阶，但有时监控基本资源消耗（如CPU或内存使用）可以帮助诊断性能瓶颈。

通常，监控系统提供仪表盘以便快速直观查看，以及警报机制，在数据管道失败或行为异常时通知您（例如，通过电子邮件或消息应用）。

> 这是一个简化的视图，显示监控如何跟踪总体状态（开始、成功、失败）以及相关指标，如时间和警报。

### 记录数据管道事件日志

监控让您对整体情况有所了解，而日志记录则提供数据管道运行期间发生的细致信息。日志通常是数据管道组件在执行时生成的文本记录。

有效的日志记录旨在捕捉有助于以下方面的信息：

- **调试：** 当数据管道失败时，日志通常是您查找错误消息并了解导致失败的事件顺序的首选。
- **审计：** 日志可以提供数据处理了什么、何时处理以及应用了哪些转换的记录。
- **性能分析：** 详细的日志可能包含特定步骤的时间戳，有助于找出瓶颈。

您应该记录什么？

- **数据管道开始/结束：** 记录数据管道运行开始和结束的确切时间。
- **阶段开始/结束：** 记录主要阶段（提取、转换、加载）的开始和结束。
- **错误：** 遇到的任何错误都必须尽可能详细地记录下来，包括失败的步骤和错误消息。
- **警告：** 不是错误但可能表示潜在问题的情况（例如，意外的数据格式、缺失的可选值）。
- **记录计数：** 记录从源读取、在转换中处理以及写入目标的记录数量有助于验证数据流。
- **重要决策：** 如果数据管道逻辑做出选择（例如，选择完全加载还是增量加载），记录该决策会很有用。

许多编程语言和ETL工具提供日志记录框架，允许您按严重程度对日志消息进行分类，通常使用以下级别：

- **INFO（信息）：** 关于数据管道进度的常规信息（例如，“开始数据提取”，“已加载1500条记录”）。
- **WARNING（警告）：** 表示发生了意外情况，但数据管道可以继续运行（例如，“发现5条记录缺少邮政编码，使用默认值替换”）。
- **ERROR（错误）：** 发生了阻止数据管道（或特定步骤）成功完成的问题（例如，“无法连接到数据库”，“因除以零导致转换失败”）。
- **DEBUG（调试）：** 非常详细的信息，在故障排除期间对开发人员很有用，但在生产环境中通常关闭。

结构良好的日志可能如下所示（简化版）：

```text
2023-10-27 08:00:01 INFO: 开始数据管道运行 ID 123。
2023-10-27 08:00:05 INFO: 提取 - 连接到源数据库 'SalesDB'。
2023-10-27 08:00:06 INFO: 提取 - 发现 528 条新销售记录。
2023-10-27 08:00:07 INFO: 提取 - 提取完成。
2023-10-27 08:00:08 INFO: 转换 - 开始数据清洗。
2023-10-27 08:00:09 WARNING: 转换 - 记录 ID 4521 日期格式无效 '2023/10/27'，跳过此记录的转换。
2023-10-27 08:00:10 INFO: 转换 - 527 条记录的转换完成。
2023-10-27 08:00:11 INFO: 加载 - 连接到目标数据仓库 'AnalyticsDW'。
2023-10-27 08:00:15 INFO: 加载 - 已将 527 条记录加载到 'daily_sales' 表中。
2023-10-27 08:00:16 INFO: 加载 - 加载完成。
2023-10-27 08:00:17 INFO: 数据管道运行 ID 123 成功完成。持续时间：16 秒。
```

如果发生错误，您可能会看到如下条目：

```text
...
2023-10-28 09:05:10 INFO: 转换 - 开始数据聚合。
2023-10-28 09:05:12 ERROR: 转换 - 聚合失败：计算产品 ID 'XYZ' 的平均价格时发生除以零错误。记录数据：{...}
2023-10-28 09:05:13 INFO: 数据管道运行 ID 124 完成但有错误。
```

实施基本的监控和日志记录对于运行可靠的ETL数据管道是必要的，即使是简单的管道也是如此。它提供了必要的反馈机制，以了解您的数据是否正确流动，并帮助您在问题出现时快速解决。大多数ETL工具都为此提供了内置功能，脚本方法通常使用标准日志库。

## 参考资料

- [Fundamentals of Data Engineering: Planning and Building Robust Data Systems](https://www.oreilly.com/library/view/fundamentals-of-data/9781098108304/) — Joe Reis, Matt Housley (2022)
  Publisher: O'Reilly Media; Pages: 447
  本书提供了关于数据工程实践的最新且完整的视角，包括数据管道可靠性、监控和可观测性等重要章节，与ETL紧密相关。
- [Designing Data-Intensive Applications: The Big Ideas Behind Reliable, Scalable, and Maintainable Systems](https://www.oreilly.com/library/view/designing-data-intensive-applications/9781491903063/) — Martin Kleppmann (2017)
  Publisher: O'Reilly Media
  数据系统领域的奠基性著作，它涵盖了可靠性和可维护性的原则，这些原则是包括ETL管道在内的任何数据工作流进行有效监控和日志记录的基础。
- [Monitoring and Logging](https://airflow.apache.org/docs/apache-airflow/3.0.6/administration-and-deployment/logging-monitoring/) — The Apache Software Foundation (2025)
  Publisher: The Apache Software Foundation
  官方文档，提供了在Apache Airflow（一个广泛使用的开源数据管道编排平台）中进行监控和日志记录的实用指南和最佳实践。
- [Monitoring and logging for Dataflow](https://cloud.google.com/dataflow/docs/guides/monitoring-and-logging) — Google Cloud (2024)
  Publisher: Google Cloud
  这份来自Google Cloud的官方指南详细介绍了在Dataflow上执行数据管道的监控和日志记录方法及最佳实践，展示了这些基础知识在云环境中的实际应用。
